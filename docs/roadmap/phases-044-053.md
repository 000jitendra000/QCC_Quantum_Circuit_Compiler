## Phase 045 — Layout-aware equivalence

| Attribute | Specification |
|---|---|

| **Source Document Page** | Page 25 (`QCC_Quantum_Circuit_Compiler_Engineering_Roadmap(1).docx`) |

### 1. Objective
Compare routed output after accounting for initial and final logical-to-physical mapping.

### 2. Required Concepts & Background
Permutation matrices, statevector bit ordering and ancilla/unused-qubit treatment.

### 3. Prerequisites & Dependencies
Phases 10 and 44.

### 4. Ordered Implementation Tasks
1. Encode logical input under initial layout.
2. Simulate routed physical circuit.
3. Decode output through final layout.
4. Check unused physical qubits or compare reduced logical state under a defined policy.
5. Apply common global-phase comparison.

### 5. Expected Files and Modules
```text
qcc-verify/src/layout_equivalence.rs; tests/equivalence/layout.rs.
```

### 6. Required Tests
Identity mapping; inserted SWAP; changed final permutation; random layouts; deliberately wrong layout.

### 7. Definition of Done
Correctly routed circuits pass and incorrect final permutations fail.

### 8. Failure Modes & Debugging Considerations
Comparing raw physical vector against logical vector; applying inverse permutation twice.

> [!IMPORTANT]
> **Explicit Architecture Refinement (ADR-0001)**:
> While task 4 mentions checking unused physical qubits or comparing reduced logical state under a defined policy, **ADR-0001 establishes the strict policy**: every physical qubit not occupied by a logical qubit starts in `|0>` and must remain in `|0>` at the end of the routed circuit. The layout-aware verifier verifies complete physical output state without silently tracing out ancillae.

### 9. Explicit Exit Gate
> **EXIT GATE**: All router tests use layout-aware semantic comparison.
