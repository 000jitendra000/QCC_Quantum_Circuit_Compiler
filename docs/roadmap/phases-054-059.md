# Milestone M6: Scheduling and Integrated Compilation

> **Milestone Code**: `M6` | **Phases Covered**: 54–59

## Scope Summary
Model target timing and resources, implement ASAP and ALAP schedulers, resource-constrained scheduling on final routed DAGs, timeline data, and integrated pipeline orchestration.

---

## Phase 054 — Target timing and resource model

| Attribute | Specification |
|---|---|
| **Phase Number** | **Phase 54** |
| **Exact Phase Title** | Target timing and resource model |
| **Milestone** | Milestone M6: Scheduling and Integrated Compilation (`M6`) |
| **Relative Engineering Effort** | **L** |
| **Source Document Page** | Page 28 (`QCC_Quantum_Circuit_Compiler_Engineering_Roadmap(1).docx`) |

### 1. Objective
Describe timing and concurrency constraints that are actually supplied by a target.

### 2. Required Concepts & Background
Operation duration, resources, measurement/readout constraints, units and calibration provenance.

### 3. Prerequisites & Dependencies
Phases 37–38 and 53.

### 4. Ordered Implementation Tasks
1. Define time and duration units.
2. Represent known and unknown operation durations distinctly.
3. Represent operation resource requirements and resource capacities.
4. Add measurement/reset durations and target-specific exclusions.
5. Record calibration provenance and timestamp.
6. Validate inconsistent or missing timing data.

### 5. Expected Files and Modules
```text
qcc-target/src/{timing,resources,calibration}.rs; tests/target/timing.rs.
```

### 6. Required Tests
Known/unknown durations; conflicting resources; invalid units; stale calibration.

### 7. Definition of Done
Target provides a coherent timing/resource model or explicitly reports unknown values.

### 8. Failure Modes & Debugging Considerations
Treating unknown as zero; assuming disconnected gates always run concurrently.

### 9. Explicit Exit Gate
> **EXIT GATE**: Timing and resource fixtures validate and preserve unknown data.

## Phase 055 — ASAP scheduler

| Attribute | Specification |
|---|---|
| **Phase Number** | **Phase 55** |
| **Exact Phase Title** | ASAP scheduler |
| **Milestone** | Milestone M6: Scheduling and Integrated Compilation (`M6`) |
| **Relative Engineering Effort** | **L** |
| **Source Document Page** | Page 29 (`QCC_Quantum_Circuit_Compiler_Engineering_Roadmap(1).docx`) |

### 1. Objective
Schedule final routed physical operations as early as dependencies and resources permit.

### 2. Required Concepts & Background
DAG scheduling, predecessor completion and resource calendars.

### 3. Prerequisites & Dependencies
Phases 43, 53–54.

### 4. Ordered Implementation Tasks
1. Consume final mapped physical DAG.
2. Traverse stable topological order.
3. Calculate earliest start from predecessor completion.
4. Check resource availability.
5. Assign start/end times and validate dependencies.

### 5. Expected Files and Modules
```text
qcc-scheduler/src/{asap,schedule,validator}.rs; tests/scheduler/asap.rs.
```

### 6. Required Tests
Hand-calculated DAGs; parallel independent gates; unequal durations; conflicts.

### 7. Definition of Done
ASAP schedule obeys all predecessor and resource constraints.

### 8. Failure Modes & Debugging Considerations
Scheduling before routing; using logical rather than physical durations.

### 9. Explicit Exit Gate
> **EXIT GATE**: ASAP result passes independent schedule validation.

### 1. Objective
Schedule operations as late as possible within a defined makespan.

### 2. Required Concepts & Background
Reverse topological traversal, latest start and slack.

### 3. Prerequisites & Dependencies
Phase 55.

### 4. Ordered Implementation Tasks
1. Define or derive makespan.
2. Traverse DAG in reverse stable topological order.
3. Calculate latest end from successors.
4. Apply resource constraints.
5. Calculate slack and validate schedule window.

### 5. Expected Files and Modules
```text
qcc-scheduler/src/alap.rs; tests/scheduler/alap.rs.
```

### 6. Required Tests
Linear DAGs; parallel paths; multi-successor nodes; zero/negative slack.

### 7. Definition of Done
ALAP preserves dependencies and fits the chosen makespan.

### 8. Failure Modes & Debugging Considerations
Confusing latest start and latest completion; negative slack not reported.

### 9. Explicit Exit Gate
> **EXIT GATE**: ALAP schedule passes timing and dependency validation.

### 4. Ordered Implementation Tasks
1. Associate operations with required physical resources.
2. Track reserved intervals.
3. Enforce capacities and conflict rules.
4. Handle readout groups and shared control resources where declared.
5. Report constraints that prevent parallel execution.

### 5. Expected Files and Modules

### 9. Explicit Exit Gate
> **EXIT GATE**: Synthetic resource-conflict schedules pass validator.

## Phase 059 — Integrated compilation pipeline

| Attribute | Specification |
|---|---|
| **Phase Number** | **Phase 59** |
| **Exact Phase Title** | Integrated compilation pipeline |
| **Milestone** | Milestone M6: Scheduling and Integrated Compilation (`M6`) |
| **Relative Engineering Effort** | **XL** |
| **Source Document Page** | Page 30 (`QCC_Quantum_Circuit_Compiler_Engineering_Roadmap(1).docx`) |

### 1. Objective
Connect logical optimization, basis translation, routing, final legality and post-routing scheduling.

### 2. Required Concepts & Background
Pass orchestration, layouts, target constraints and end-to-end provenance.

### 3. Prerequisites & Dependencies
Phases 28–58.

### 4. Ordered Implementation Tasks
1. Define compiler configuration and pipeline stages.
2. Optimize logical circuit.
3. Translate to target routing basis.
4. Choose initial placement and route.
5. Apply final target-specific translation if required.
6. Run final target legality validation.
7. Schedule the final mapped circuit only after routing.
8. Verify layout-aware semantics and produce report.

### 5. Expected Files and Modules
```text
qcc-core/src/compiler/{pipeline,config,result}.rs; tests/compiler/end_to_end.rs.
```

### 6. Required Tests
Bell; line/ring topologies; directed target; impossible topology; timing target.

### 7. Definition of Done
A supported circuit passes the entire target pipeline deterministically.

### 8. Failure Modes & Debugging Considerations
Stale layout after final translation; scheduling pre-route; missing final legality check.

### 9. Explicit Exit Gate
> **EXIT GATE**: End-to-end compilation output is legal, semantically verified and optionally scheduled. Milestone M7 — Dynamic simulation and non-unitary semantics
