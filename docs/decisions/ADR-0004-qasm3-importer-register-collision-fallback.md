# ADR-0004: OpenQASM 3 Register Symbol-Collision Adapter for Pinned Qiskit Importer

## Status
**Accepted** (12 November 2026)

## Context
During **Roadmap v3.1 — M7 Session 2 (Phase 61 / Phase 63 QASM-import compatibility)**, real physical OpenQASM 3 circuits generated by QCC (`examples/showcase.qasm`, `examples/routing.qasm`, `tests/fixtures/qasm3/rotations.qasm`, and `tests/fixtures/qasm3/global_phase.qasm` compiled via `qcc compile --target linear` and `--target ring`) were tested against the pinned independent oracle environment:

- Python `3.12.3`
- `openqasm3==1.0.1`
- `qiskit==2.6.2`
- `qiskit-qasm3-import==0.6.0`

Testing revealed two critical empirical facts:
1. `openqasm3.parser.parse()` parses all unmodified QCC-emitted physical OpenQASM 3 files without error.
2. `qiskit.qasm3.loads()` (`qiskit-qasm3-import==0.6.0`) **fails immediately on 100% of unmodified QCC-emitted physical OpenQASM 3 circuits containing gates** with:
   ```text
   QASM3ImporterError: "4,0: Symbol 'p' already inserted in symbol table in this scope: Scope.GLOBAL"
   ```
   Root cause: QCC's hardware routers emit the physical quantum register as `qubit[N] p;`, and `OpenQasmEmitter` emits `include "stdgates.inc";` whenever standard gates are present. In `qiskit-qasm3-import==0.6.0`, visiting `include "stdgates.inc";` inserts 30 gate symbols into `Scope.GLOBAL`, including `"p"` (`PhaseGate`). Any global register named `p` (or `x`, `y`, `z`, `h`, `s`, `t`, `u1`–`u3`, `cx`, etc.) triggers a global symbol-table collision error.

Meanwhile:
- Modifying QCC's Rust compiler/router register naming from `"p"` in Session 2 would break scope separation and could still fail for valid user frontend circuits whose registers use single-letter names such as `qubit[n] p;` or `qubit[n] x;`.
- Manual fixture rewriting is explicitly unacceptable for independent verification.

## Decision
1. **Preserve QCC Rust Emission Unchanged**: Leave QCC's Rust compiler and `OpenQasmEmitter` untouched (`qubit[N] p;` preserved).
2. **Adopt a Strictly Scoped, Semantics-Preserving AST Register Alpha-Renaming Adapter** in `tools/independent_oracle/qasm3_compat.py` (`adapt_colliding_registers`):
   - Always parse the raw OpenQASM 3 source first with `openqasm3.parser.parse()`.
   - Attempt raw `qiskit.qasm3.loads(raw_qasm)` first to record whether a collision occurred.
   - Only when `qiskit-qasm3-import` raises `Scope.GLOBAL` `"already inserted in symbol table"` (and only when all statements belong to the verified flat top-level circuit subset—refusing custom `gate` definitions, subroutines, calibrations, branching/loops, or aliases):
     - Deterministically alpha-rename colliding top-level `QubitDeclaration` and `ClassicalDeclaration` identifiers (e.g., `p` -> `qcc_reg_p`) using a fresh `[a-z]\w*` identifier absent from all AST identifiers and `_STDGATES` / `_BUILTINS`.
     - Rewrite matching `Identifier` / `IndexedIdentifier` references **strictly inside operand/target slots** (`QuantumGate.qubits`, `QuantumPhase.qubits`, `QuantumMeasurement.qubit`, `QuantumMeasurementStatement.target`, `QuantumReset.qubits`, `QuantumBarrier.qubits`). Never modify `QuantumGate.name` (so a `p(lambda)` gate call remains gate `p`), numeric constants, parameters, or `gphase(...)`.
     - Re-serialize with `openqasm3.dumps()` and verify AST operation-signature invariance (exact sequence of gate names, operand counts, parameter arities, `gphase`, measurements, resets, barriers).
3. **Fail Closed on Unsupported Constructs**:
   - Never silently drop `gphase`, gates, measurements, resets, or parameters.
   - Explicitly classify unsupported QCC/OpenQASM constructs (`PARSE_ERROR`, `UNSUPPORTED_NON_UNITARY`, `UNSUPPORTED_UNBOUND_PARAM`, `UNSUPPORTED_CONSTRUCT` including QCC-accepted `sxdg`, `i`, and lowercase `u` that `qiskit-qasm3-import==0.6.0` lacks in `_STDGATES`).

## Consequences
- Every QCC-emitted physical OpenQASM 3 circuit using `{rz, sx, cx}` + `gphase` + `qubit[N] p;` imports deterministically into Qiskit `QuantumCircuit`, constructs unitary `Operator(qc)` and `Statevector.from_instruction(qc)`, and preserves exact `exp(i * global_phase)` and `logical_to_physical` qubit ordering without touching Rust code.
- Session 3's oracle comparator can consume `probe_qasm3_compatibility` / `validate_manifest_consistency` directly while remaining mathematically identical to raw OpenQASM 3 semantics.
