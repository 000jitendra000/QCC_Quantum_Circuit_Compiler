## 2. Theoretical & Algorithmic Formulation

Phase 52 completes the core routing engine of SABRE (*SWAP-based Bounded-depth Routing Engine*, ASPLOS 2019, Li et al.) by implementing reverse circuit traversal and multi-round iterative layout refinement:

### 2.1 Reverse Circuit Traversal
In forward routing, initial placement choices made without future sight can lead to costly SWAP overheads early in the circuit. SABRE resolves this through reverse traversal:
1. **Circuit Reversal**: A reversed circuit $C_{\text{rev}}$ is generated by inverting the DAG dependency edges and reversing the operation sequence.
2. **Explicit Global Phase Inversion**: To maintain strict unitary semantics across reversals, the circuit global phase is conjugated:
   $$\phi_{\text{rev}} = -\phi_{\text{fwd}}$$
3. **Immutability of Original Circuit**: The original logical circuit $C$ is never mutated. $C_{\text{rev}}$ is constructed as a separate transactional `Circuit` instance.
4. **Reverse Routing Pass**: Routing $C_{\text{rev}}$ begins from the final layout of the forward pass ($L_{\text{fwd\_final}}$). As reverse routing proceeds, the earliest forward operations (encountered last in reverse order) naturally bring interacting logical qubits into adjacent physical positions.

### 2.2 Permutation and Layout Invariants
A critical mathematical distinction in layout-aware compilation is between layout assignments and permutations:
- A layout $L: Q \to P$ maps logical qubit $q$ to physical qubit $p$.
- At the conclusion of reverse routing, logical qubit $q$ resides at physical qubit $p' = L_{\text{rev\_final}}(q)$.
- Because reverse routing finished with the earliest operations of the forward circuit, interacting operands are now physically adjacent.
- **Fundamental Invariant**: The final layout of reverse routing is directly used as the candidate initial layout for the next forward pass:
  $$L_{\text{initial}}^{\text{candidate}} = L_{\text{rev\_final}}$$
- **No Permutation Inversion**: Inverting $L$ into $L^{-1}$ would map physical qubit IDs back to logical qubit IDs, corrupting asymmetric initial configurations. QCC strictly preserves layout orientation without improper inversions.

### 2.3 Iterative Layout Refinement & Multi-Metric Acceptance
Given initial layout $L_0$ (user-provided or identity):
1. **Round 1 Forward Pass**: Route forward from $L_0$, yielding routed circuit $C^{(1)}$, metrics $M^{(1)}$, and final layout $L_{\text{fwd\_final}}^{(1)}$.
2. **Iterative Refinement (Rounds $2 \dots R$)**:
   - Reverse traverse from $L_{\text{fwd\_final}}^{(r-1)}$, yielding $L_{\text{rev\_final}}^{(r-1)}$.
   - Forward traverse from candidate initial layout $L_{\text{initial}}^{(r)} = L_{\text{rev\_final}}^{(r-1)}$, yielding candidate circuit $C^{(r)}$ and metrics $M^{(r)}$.
   - **Acceptance Criterion**: Candidate round $r$ is accepted if it strictly improves over the current best round:
     1. Primary: strictly smaller composite weighted cost: $\text{Cost}(M^{(r)}) < \text{Cost}(M_{\text{best}})$ (by $> 10^{-9}$).
     2. Secondary tie-breaker: strictly fewer inserted routing SWAPs: $N_{\text{SWAP}}^{(r)} < N_{\text{SWAP}}^{\text{best}}$.
     3. Tertiary tie-breaker: strictly lower critical-path circuit depth: $D^{(r)} < D^{\text{best}}$.
     4. Quaternary tie-breaker: strictly lower two-qubit gate depth: $D_{2Q}^{(r)} < D_{2Q}^{\text{best}}$.
   - If accepted, update best circuit, layout, and metrics. If rejected, retain current best.
3. **Strict Convergence**: The router tracks round-by-round history in `RefinementSummary`, returning the exact winning round and metrics.

### 2.4 ADR-0001 Strict Ancilla Zero-State Policy
On partially occupied devices ($n_{\text{logical}} < n_{\text{physical}}$), unused physical qubits begin in $|0\rangle$ and must return to $|0\rangle$ at circuit termination. Bidirectional SABRE preserves ancilla state across all forward and reverse iterations:
- Layout-aware semantic verification via `LayoutEquivalenceChecker` verifies the full $2^{n_{\text{physical}}}$-dimensional statevector equivalence up to a single global phase.

## 3. Implementation Overview

1. **Layout Refinement Abstractions ([`src/routing/sabre/layout_refinement.rs`](file:///home/ronanki_jitendra/rust/QCC/src/routing/sabre/layout_refinement.rs))**:
   - `RefinementRoundRecord`: Captures per-round metrics, inserted SWAP counts, critical path depths, and initial/final layout snapshots.
   - `RefinementSummary`: Collects round progression, winning round index, winning SWAP count, winning depth, and winning cost.
   - `is_refinement_improvement`: Hierarchical multi-objective comparator enforcing composite cost, SWAP count, critical depth, and two-qubit depth tie-breakers.

2. **Bidirectional Router & Reverse Traversal ([`src/routing/sabre/bidirectional.rs`](file:///home/ronanki_jitendra/rust/QCC/src/routing/sabre/bidirectional.rs))**:
   - `reverse_circuit`: Constructs $C_{\text{rev}}$ with inverted dependency edges, reversed topological order, and conjugated global phase without mutating $C$.
   - `emit_non_2q_operation`: Accurately maps 1Q gates, measurements, resets, barriers, and classical operations with full provenance tracking.
   - `SabreRouterConfig`: Encapsulates refinement rounds, maximum iterations, lookahead weight $W$, decay increment $\delta$, and optional RNG seed.
   - `SabreRouterReport`: Detailed routing telemetry containing final layout, SWAP counts, inserted operations, comprehensive metrics, and refinement summary.
   - `SabreBidirectionalRouter`:
     - `route_single_pass`: High-efficiency single-pass router executing 1Q gates eagerly, validating front-layer 2Q gates, and evaluating candidate SWAPs using `SabreHeuristic`.
     - `route_circuit`: Multi-round coordinator executing forward/reverse layout refinement, maintaining layout invariants, and returning the optimal routed circuit.
     - `validate_report`: Validates output circuit with `TargetLegalityValidator` and verifies layout equivalence against original logical circuit.
